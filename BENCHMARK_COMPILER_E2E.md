## 2. Deep Root-Cause Analysis of Compiler Errors

### ① The "Zig v0.16.0 Breaking Change" Trap
* **Compiler Error Observed**:
  ```
  error: root source file struct 'heap' has no member named 'GeneralPurposeAllocator'
  error: extra capture in for loop (for (args) |arg, i|)
  ```
* **Why LLMs Fail**:
  * All major LLMs were trained on millions of lines of Zig v0.11–v0.13 code (`std.process.argsAlloc`, `for (items) |item, idx|`).
  * In Zig v0.16.0, `main` requires `pub fn main(init: std.process.Init)` and for-loops require `for (items, 0..) |item, idx|`.
* **The `doc-engine` Lesson**:
  * Short text snippets are insufficient for breaking syntax changes; injecting **Tier 2 Complete Code Templates (`doc-engine get curated:zig-0.16-std`)** is strictly required for 100% compilation success.

### ② The "React 18 vs 19 Type Bleed" Trap
* **Compiler Error Observed**:
  ```
  error TS2305: Module '"react-dom"' has no exported member 'useFormState'.
  ```
* **Why LLMs Fail**:
  * LLMs mix React 18 Canary types with stable `@types/react-dom@18.2.0`, causing TypeScript build failures.
* **The `doc-engine` Lesson**:
  * Grounding via `--ver 18` enforces standard `useTransition` / `useState` patterns, ensuring zero TypeScript compilation errors.

## 3. Recommended Multi-Tier Retrieval Protocol for AI Agents

To achieve a 100% compilation pass rate in production:

1. **Step 1 (Fast Triaging)**:
   * Run `doc-engine search "<query>" --lib <lib> --ver <ver>` to locate relevant module IDs (~1.2ms).
2. **Step 2 (Deep Template Extraction)**:
   * Run `doc-engine get <matched_doc_id>` to inject the complete, verified compilable code block into LLM context.
3. **Step 3 (Lockfile Grounding)**:
   * Always let `tools.py` auto-sniff `Cargo.lock` and `package-lock.json` before selecting API versions.
