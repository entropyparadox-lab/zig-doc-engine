# Zig v0.16.0 LLM Drift FAQ & Compiler Error Troubleshooting Guide

A curated catalog of compiler errors, build failures, and breaking standard library shifts commonly generated by LLMs trained on older Zig versions (v0.11 ~ v0.13) vs modern Zig v0.16.0+.

---

## 1. CI / GitHub Actions: Zig Download Fails with HTTP 404

### ❌ Error Symptom
```text
Fetching zig-linux-x86_64-0.16.0.tar.xz
Attempting official: https://ziglang.org/builds
##[error]Unexpected HTTP response: 404
##[error]Unable to locate executable file: zig.
```

### 🔍 Root Cause (LLM Hallucination / Deprecated Action)
1. Older LLMs generate `uses: mlugg/setup-zig@v1`.
2. As of Zig v0.14.1+, release tarball naming flipped from `zig-{os}-{arch}` (`zig-linux-x86_64`) to standard target-triple order `zig-{arch}-{os}` (`zig-x86_64-linux-0.16.0.tar.xz`).
3. `@v1` is deprecated, hardcodes legacy URLs/filenames, and fails with 404.

### ✅ Modern Fix (v0.16.0+)
Update to **`mlugg/setup-zig@v2`** in `.github/workflows/ci.yml`:
```yaml
- name: Setup Zig v0.16.0
  uses: mlugg/setup-zig@v2
  with:
    version: 0.16.0
    use-cache: true
```

## 2. `build.zig`: `root_source_file` Not Found in `ExecutableOptions`

### ❌ Error Symptom
```text
build.zig:17:28: error: no field named 'root_source_file' in struct 'std.Build.ExecutableOptions'
    const exe = b.addExecutable(.{
                           ^
```

### 🔍 Root Cause
In Zig v0.16.0+, target and optimization settings are unified into `std.Build.Module`. `b.addExecutable` and `b.addLibrary` now require `.root_module` instead of `.root_source_file`.

### ✅ Modern Fix (v0.16.0+)
```zig
// 1. Create root module
const exe_mod = b.createModule(.{
    .root_source_file = b.path("src/main.zig"),
    .target = target,
    .optimize = optimize,
});

// 2. Pass root_module to executable
const exe = b.addExecutable(.{
    .name = "my-app",
    .root_module = exe_mod,
});
b.installArtifact(exe);
```

## 3. Entry Point: `main` Signature & CLI Argument Parsing

### ❌ Error Symptom
```text
error: root.main has signature 'pub fn main() void' but root file requires 'pub fn main(init: std.process.Init) !void'
error: struct 'std.process' has no member named 'argsAlloc'
```

### 🔍 Root Cause
Zig v0.16.0 standardizes the entry point interface via `std.process.Init`, passing process arena, minimal args iterator, and I/O context directly to `main`.

### ✅ Modern Fix (v0.16.0+)
```zig
const std = @import("std");

pub fn main(init: std.process.Init) !void {
    const allocator = init.arena.allocator();

    var args_list: std.ArrayList([]const u8) = .empty;
    defer args_list.deinit(allocator);

    var it = init.minimal.args.iterate();
    while (it.next()) |arg| {
        try args_list.append(allocator, std.mem.sliceTo(arg, 0));
    }
    const args = args_list.items;
    _ = args;
}
```

## 4. `std.ArrayList`: Missing `.init(allocator)` Member

### ❌ Error Symptom
```text
src/main.zig:15:37: error: struct 'std.array_list.ArrayList' has no member named 'init'
    var list = std.ArrayList(u8).init(allocator);
                                ^~~~
```

### 🔍 Root Cause
`std.ArrayList` in v0.16.0 uses unmanaged semantics by default. The allocator is passed directly to mutator methods (`append`, `deinit`, etc.) rather than stored in the struct.

### ✅ Modern Fix (v0.16.0+)
```zig
// Initialize with .empty
var list: std.ArrayList(u8) = .empty;
defer list.deinit(allocator);

// Pass allocator on each mutating operation
try list.append(allocator, 42);
```

## 5. `for` Loop: Two Captures without Explicit Index Range

### ❌ Error Symptom
```text
src/main.zig:20:25: error: expected 1 capture, found 2
    for (items) |item, idx| {
                        ^~~
```

### 🔍 Root Cause
Zig requires an explicit multi-sequence range `0..` when capturing loop iteration indices.

### ✅ Modern Fix (v0.16.0+)
```zig
for (items, 0..) |item, idx| {
    std.debug.print("Index {d}: {any}\n", .{ idx, item });
}
```

## 6. Environment Variables: `std.posix.getenv` Deprecated

### ❌ Error Symptom
```text
error: namespace 'std.posix' has no member named 'getenv'
error: struct 'std.process' has no member named 'getEnvVarOwned'
```

### 🔍 Root Cause
Environment variable access is now explicitly retrieved through `init.minimal.environ`.

### ✅ Modern Fix (v0.16.0+)
```zig
pub fn main(init: std.process.Init) !void {
    const allocator = init.arena.allocator();
    
    if (init.minimal.environ.getAlloc(allocator, "MY_ENV")) |val| {
        defer allocator.free(val);
        std.debug.print("Value: {s}\n", .{val});
    } else |_| {
        // Not found or error
    }
}
```

## 7. C-ABI Calling Convention: `.C` Uppercase Tag Error

### ❌ Error Symptom
```text
src/c_api.zig:5:34: error: enum 'std.builtin.CallingConvention' has no tag named 'C'
export fn compute() callconv(.C) i32 { ... }
                             ^~
```

### 🔍 Root Cause
The calling convention tag was lowercased to `.c` in recent Zig versions.

### ✅ Modern Fix (v0.16.0+)
```zig
export fn compute() callconv(.c) i32 {
    return 42;
}

// Or simply 'export fn' which defaults to C ABI:
export fn compute_default() i32 {
    return 42;
}
```

## 8. Summary Table: LLM Drift Cheat Sheet

| Category | Outdated LLM Hallucination (0.11 ~ 0.13) | Modern Grounding (Zig v0.16.0+) |
| :--- | :--- | :--- |
| **CI Action** | `uses: mlugg/setup-zig@v1` | `uses: mlugg/setup-zig@v2` |
| **`main` Entry** | `pub fn main() !void` | `pub fn main(init: std.process.Init) !void` |
| **CLI Args** | `std.process.argsAlloc(allocator)` | `init.minimal.args.iterate()` |
| **Env Vars** | `std.posix.getenv("KEY")` | `init.minimal.environ.getAlloc(allocator, "KEY")` |
| **`ArrayList`** | `var l = std.ArrayList(T).init(a);` | `var l: std.ArrayList(T) = .empty;` |
| **`build.zig`** | `b.addExecutable(.{ .root_source_file = ... })` | `b.addExecutable(.{ .root_module = mod })` |
| **`for` loop index**| `for (items) \|item, idx\|` | `for (items, 0..) \|item, idx\|` |
| **C ABI Tag** | `callconv(.C)` | `callconv(.c)` or bare `export fn` |
